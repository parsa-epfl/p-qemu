Covers `dynamic_barrier_polling_t` (the polling barrier in `util/dynamic_barrier.c`), the MTTCG path in `accel/tcg/tcg-accel-ops-quantum.c` vs the RR path in `accel/tcg/tcg-accel-ops-rr.c`, the TB-injected `gen_helper_check_and_deduce_quantum` budget decrement, `EXCP_QUANTUM` exception flow, `increase_quantum_time()` that writes the parallel-mode `QEMU_CLOCK_VIRTUAL`, the `-quantum size=…,check_period=…` parsing in `softmmu/quantum.c`, per-core `ip100ns` loading from `core_info.csv` and the per-core `cpu_virtual_time[]` array, the three wait blocks in `mttcg_cpu_thread_fn` (post-TB-exit / pre-atomic-op / post-idle), and the `stop_request ∈ {0,1,2}` broadcast word that doubles as the snapshot/pause signal. **Does NOT cover MNQ (Multi-Node Quantum) — the across-machines WWT barrier lives in the sibling `qemu-pdes/` repo (included here via `-iquote ../qemu-pdes/include`); use the `multi-node` skill for that.** TRIGGER when the user mentions PWQ / dynamic_barrier / quantum_barrier / quantum_size / check_period / ip100ns / `tcg-accel-ops-quantum.c` / `tcg-accel-ops-rr.c` / `cpu_virtual_time` / `quantum_budget` / EXCP_QUANTUM / `pf_periodic_check_cb` / "core stuck at barrier" / "savevm not firing from quantum" / parallel vs RR mode / `quantum_enabled()` vs `icount_enabled()`. SKIP for MNQ / `qemu-pdes/` / WWT / `quanta_sync` / `pdes_pause` / `pdes_play` (multi-node skill) or upstream-QEMU TCG internals that this fork doesn't customise.
